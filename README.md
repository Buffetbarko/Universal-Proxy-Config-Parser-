# proxy-parser

Парсер и проверщик прокси на Go. Собирает конфигурации из источников, удаляет дубликаты, проверяет доступность и сохраняет результаты в файлы, которые можно открыть в клиентах.

## Возможности

- Сбор ссылок и конфигураций из источников, перечисленных в `config.yaml`: Telegram, HTTP-подписок, GitHub и локальной папки `input/`.
- Разбор VLESS, VMess, Hysteria2, TUIC, MTProto/MTProxy, MTProxy WSS, SOCKS5, HTTP/HTTPS и Happ-ссылок.
- Очистка, нормализация и удаление дубликатов.
- DNS/TCP-предварительная проверка, проверка прокси по протоколу, измерение задержки и определение страны по GeoIP.
- Строгая проверка MTProto: парсер подтверждает ответ Telegram, а не только открытие TCP-соединения.
- Классификация результатов по правилам и спискам из `config.yaml`.
- Экспорт в TXT, JSON, Clash YAML, sing-box, Xray и Happ-форматы; история запусков и конфигураций сохраняется в SQLite.
- Повторные циклы с заданным интервалом.

Проверка не гарантирует, что прокси останется доступным после завершения запуска: публичные прокси могут перестать работать в любой момент.

## Запуск в Termux

### 1. Установить необходимые пакеты

В Termux выполните:

```bash
pkg update -y && pkg upgrade -y
pkg install -y golang unzip
termux-setup-storage
```

Подтвердите доступ Termux к файлам устройства. Для сборки нужен Go версии, совместимой с `go.mod` (в этой версии проекта указана Go 1.25).

Скачайте ZIP-релиз проекта в папку `Download` и сохраните его как `proxy-parser.zip`. Внутри архива должна быть верхняя папка `proxy-parser/`. Если загружаете проект на GitHub, разместите ZIP как файл релиза; автоматически созданный GitHub архив исходников может иметь другое имя и другую верхнюю папку.

### 2. Распаковать проект и собрать программы

```bash
termux-wake-lock
rm -rf ~/proxy-parser
unzip ~/storage/downloads/proxy-parser.zip -d ~/proxy-parser
cd ~/proxy-parser/proxy-parser
go build -ldflags="-s -w" -o parser ./cmd/parser/
go build -o bot ./cmd/bot/
```

> `rm -rf ~/proxy-parser` удаляет предыдущую папку установки парсера в домашнем каталоге Termux. Если там есть нужные файлы, сохраните их перед выполнением команды.

Первая сборка скачает Go-зависимости и требует подключения к интернету. Бот собирается отдельно; для запуска только парсера собирать его необязательно.

## Запуск парсера

Выберите **одну** команду:

```bash
./parser
```

```bash
./parser --interval 3h
```

```bash
./parser --interval 1h
```

Без параметра парсер запускает цикл сразу, затем повторяет его каждые 4 часа. `--interval 3h` и `--interval 1h` задают интервал между циклами. Чтобы выполнить только один цикл и выйти:

```bash
./parser --once
```

Остановить постоянно работающий парсер можно сочетанием `Ctrl+C`. После остановки, если парсер больше не нужен в фоне, освободите блокировку сна:

```bash
termux-wake-unlock
```

## Где найти проверенные конфигурации

После завершения цикла результаты находятся в папке `output/` рядом с бинарным файлом `parser`.

Основные файлы:

| Файл | Содержимое |
| --- | --- |
| `output/proxies.txt` | Проверенные VPN-конфигурации в виде ссылок |
| `output/telegram.txt` | Проверенные MTProto/Telegram-прокси |
| `output/proxies.yaml` | Конфигурации для Clash |
| `output/singbox.json` | Конфигурация sing-box |
| `output/xray.json` | Конфигурация Xray |
| `output/happ.json` | Экспорт Happ |

Также парсер создаёт каталоги с результатами, разделёнными по классификации:

- `output/white_list/proxies.txt` — проверенные VPN-конфигурации класса `white`.
- `output/white_list/mtproto.txt` — проверенные MTProto-прокси класса `white`.
- `output/black_list/proxies.txt` и `output/black_list/mtproto.txt` — проверенные конфигурации класса `black`.

Категории `white_list` и `black_list` обозначают классификацию по настройкам и спискам проекта, а не статус «работает/не работает»: в эти групповые файлы попадают прошедшие проверку прокси соответствующего класса. Настройки источников, фильтров и исключённых стран находятся в `config.yaml`.

Скопировать журнал и папку с результатами в общую папку `Download`:

```bash
cp ~/proxy-parser/proxy-parser/logs/parser.log ~/storage/downloads/parser.log
cp -r ~/proxy-parser/proxy-parser/output ~/storage/downloads/proxy-parser-output
```

Если `proxy-parser-output` уже существует, сначала переместите или удалите предыдущую выгрузку, чтобы новая не оказалась вложенной в неё. В файловом менеджере Android откройте `Download`, затем `proxy-parser-output`.

Журнал запуска находится в `logs/parser.log`. Он помогает выяснить, сколько конфигураций найдено и проверено, какие ошибки возникли и где записаны результаты.

## Важные замечания

- Для полноценной проверки некоторых протоколов используются Xray и Hysteria2. В `config.yaml` включена попытка автоматической загрузки этих программ; если проверка соответствующего протокола не проходит, посмотрите предупреждения в `logs/parser.log`.
- Парсер проверяет доступность в момент запуска. Результат проверки — не гарантия постоянной работоспособности прокси.
- Не публикуйте в открытом репозитории личные конфигурации, токены Telegram-бота и другие секреты.
